# 논숲 시험 응시 화면 — Claude Design 요청 프롬프트

> 사용법: **[공통 블록]을 먼저 붙이고, 그 아래에 만들고 싶은 화면 블록 하나를 이어 붙여** 요청한다.
> 5개 화면을 한 번에 요청하지 말 것. 화면당 정보 밀도가 높아 품질이 떨어진다.

# [공통 블록] — 매 요청마다 상단에 포함

## 서비스 컨텍스트

'논숲'은 고3·재수생 대상 AI 논술 학습 플랫폼이다. 유저는 대학별 논술 기출/기출변형 시험에 응시해 답안을 작성하고, AI 채점 결과를 받는다. 지금 만들 화면은 **실제로 답안을 작성하는 응시 환경**이다.

핵심 정서: 유저는 지금 **긴장한 수험생**이다. 화면이 산만하면 답안에 집중할 수 없다. 화려함보다 **집중과 신뢰**가 우선이다. 동시에 이건 실전이 아니라 모의고사이므로, 위압적이거나 감시당하는 느낌은 피해야 한다.

## 브랜드 (하드 제약)

```
Primary Deep    #00661A   주요 액션, 강조 텍스트
Primary         #008B48   브랜드 그린
Accent Light    #94EF90   포인트, 진행 상태
Accent Pale     #CBF6C3   배경 강조
Lime            #B5E82A   보조 액센트 (절제해서 사용)
Warning         #EFAC03   주의 상태
Warning Bg      #FDF0CC
Ink             #111827   본문

```

- 한글 폰트: **SUIT** (Bold는 디스플레이용)
- 마스코트: 완두콩 (둥근 연두색 콩). 응시 화면에서는 **사용하지 않는다.** 시험 중 캐릭터 노출은 집중을 방해한다. 안내·완료 화면에서만 절제해서 허용.

## 하드 제약 (반드시 지킬 것)

1. **카피는 아래 제공된 문구를 그대로 사용한다.** 임의로 바꾸거나 의역하지 않는다.
2. **PC 전용.** 데스크톱 뷰포트 기준으로만 설계한다 (1440 기준, 최소 1280).
3. 지정된 **정보 우선순위**를 지킨다. 우선순위가 높은 요소가 시각적으로 더 강해야 한다.
4. 색상은 위 토큰만 사용한다.

## 열어둘 것 (자유롭게 판단)

- 레이아웃 구조와 그리드, 여백, 폰트 크기·굵기
- 컴포넌트의 형태 (카드/보더/그림자/라운드 처리)
- 상태 표현 방식 (배지·점·바 등 무엇을 쓸지)
- 마이크로 인터랙션과 전환 모션
- 아이콘 유무와 스타일

# [화면 1] 응시 안내 모달

응시하기 버튼을 누르면 뜨는 모달. **유저가 여기서 놓친 정보는 전부 CS로 돌아온다.** 특히 자동 제출과 완두콩 차감.

## 상단 시험 정보

```
경희대학교 2026학년도 인문계열 모의논술
문항 3개 · 제한 시간 90분 · 완두콩 50
```

## 안내 문구 (순서 고정)

```
응시를 시작하면 완두콩 50개가 차감돼요. 중간에 나가도 돌려드리지 않아요.
오늘 남은 응시 횟수는 1회예요.
제한 시간이 모두 지나면, 작성 중이던 답안이 그대로 자동 제출돼요.
일시정지는 횟수 제한 없이 쓸 수 있어요. 다만 정지하는 동안에는 문제와 답안이 보이지 않아요.
작성 중인 답안은 자동으로 저장돼요.
일시정지 상태가 아니라면, 창을 닫아도 시간은 계속 흘러요.
분량이 너무 부족하면 제출이 제한될 수 있어요.
답안 입력란에는 붙여넣기를 할 수 없어요.
시험 응시는 PC에서만 가능해요.
```

**3번째와 4번째 문구는 나머지보다 시각적으로 강해야 한다.** 자동 제출과 일시정지는 유저가 가장 놓치기 쉬우면서 사후 분쟁이 가장 많은 항목이다.

## 하단

```
체크박스: 위 내용을 모두 확인했어요
버튼: 취소 / 응시 시작
```

- 체크박스 미체크 시 [응시 시작] 비활성 상태도 함께 보여줄 것.

## 정보 우선순위

1순위 시험명 · 제한 시간 → 2순위 자동 제출/일시정지 고지 → 3순위 나머지 고지 → 4순위 액션 버튼

# [화면 2] 카운트다운

응시 시작 직후 3초간 노출되는 전체 화면 오버레이.

```
3 → 2 → 1 → 시작
```

- 유저를 진정시키면서 시험 모드로 전환시키는 역할.
- 숫자 전환 모션은 자유. 다만 **급박하거나 불안을 자극하는 연출은 피할 것.**
- 배경에 시험 화면이 살짝 비치는 구성도 가능.

# [화면 3] 응시 화면 (핵심 화면)

가장 중요한 화면. 유저가 90분간 머무는 공간이다.

## 구성 요소

**헤더**
- 시험명
- **타이머** — `남은 시간 72:14`
- 일시정지 버튼
- 문항 네비게이션 (1 / 2 / 3)
- 제출 버튼

**본문 — 2단 구성**
- 좌: 제시문 영역 (독립 스크롤, 가/나/다 등 복수 제시문, 매우 길다)
- 우: 문제 발문 + 원고지 입력 영역

**발문 영역**
```
1번 문항
제시문 (가)와 (나)에 나타난 관점의 차이를 설명하고, 이를 바탕으로 (다)의 사례를 평가하시오.
권장 분량 150자 ~ 250자
```

**원고지 입력 영역**
- 20칸 × N행의 실제 원고지 격자. 1칸 = 1글자.
- 이 화면의 시각적 주인공. **종이 원고지의 질감과 디지털 입력의 명료함 사이에서 균형**을 잡을 것.
- 커서가 위치한 칸이 명확히 보여야 한다.

**하단 상태 바**
- 글자수 `152 / 250자`
- 저장 상태 `방금 저장됨`

## 상태 표현이 필요한 것

**문항 네비게이션 — 3가지 상태**
```
미작성   (0자)
작성 중  (1자 이상 ~ 권장 분량 미만)
충족     (권장 분량 이상)
```
+ 현재 보고 있는 문항 표시

**타이머 — 3가지 상태**
```
평상    (10분 초과)
주의    (10분 이하)
경고    (1분 이하)
```

## 카피 (고정)

```
남은 시간
권장 분량 150자 ~ 250자
방금 저장됨
저장 중…
저장 실패 — 다시 시도
10분 남았어요.
5분 남았어요.
1분 남았어요.
답안 입력란에는 붙여넣기를 할 수 없어요.
```

## 정보 우선순위

1순위 원고지 입력 영역 → 2순위 타이머 → 3순위 제시문 → 4순위 발문 → 5순위 문항 네비 · 글자수 → 6순위 저장 상태 · 일시정지

> 타이머가 2순위지만 **불안을 자극할 만큼 크거나 붉어서는 안 된다.** 평상 상태에서는 조용히 존재하다가 잔여 시간이 줄어들 때만 존재감이 커지는 방식이 적절하다.

# [화면 4] 일시정지 오버레이

일시정지 버튼을 누르면 화면 전체를 덮는 오버레이. **제시문·발문·답안이 전혀 보이지 않아야 한다.** 이건 기능 요구사항이므로 반투명이나 블러로 내용이 읽히면 안 된다.

## 노출 요소

```
잠시 멈췄어요
다녀오셔도 괜찮아요. 재개하기 전까지 시간은 흐르지 않아요.

남은 시간 72:14   ← 정지된 상태임이 보여야 함

버튼: 응시 재개
```

- **정서적 톤이 중요하다.** 유저는 지금 화장실에 가거나 밥을 먹으러 갔다. 시험이 중단됐다는 불안이 아니라 **안심**을 줘야 한다.
- 타이머가 "멈춰 있다"는 사실이 시각적으로 읽혀야 한다. 숫자만 정지시키지 말 것.

# [화면 5] 제출 확인 모달

제출 버튼을 누르면 뜨는 최종 확인. 문항별 작성 현황을 요약해 보여준다.

## 구성

```
제출하면 답안을 수정할 수 없어요.

1번 문항   210자   충족
2번 문항    88자   분량 부족 — 75자 이상 필요
3번 문항     0자   미작성

남은 시간 12:04

버튼: 계속 작성 / 제출하기
```

- **1개 문항이라도 기준 미달이면 [제출하기]는 비활성.** 비활성 상태를 함께 보여줄 것.
- 미달 문항 행은 클릭해서 해당 문항으로 이동할 수 있다.
- 남은 시간을 함께 보여주는 이유는 **"아직 시간이 있다"를 인지시켜 성급한 제출을 막기 위해서**다. 이 의도가 읽히게 배치할 것.

## 정보 우선순위

1순위 문항별 현황 테이블 → 2순위 수정 불가 경고 → 3순위 남은 시간 → 4순위 버튼
